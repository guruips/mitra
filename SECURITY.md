# Security Policy

## Reporting Security Vulnerabilities

Kami sangat serius tentang keamanan. Jika Anda menemukan vulnerability, **jangan** membuka public issue.

Sebaliknya, silakan email ke: **security@catatangurulps.com**

### Informasi yang Harus Disertakan

1. Deskripsi vulnerability
2. File atau kode yang terkena dampak
3. Langkah untuk reproduce
4. Potential impact
5. Suggested fix (jika ada)

## Respon Timeline

- **24 jam**: Konfirmasi penerimaan laporan
- **48 jam**: Initial assessment
- **7 hari**: Proposed timeline untuk fix
- **30 hari**: Target untuk release patch

## Disclosure Policy

- Kami akan bekerja dengan pelapor untuk fix vulnerability
- Credit akan diberikan kepada pelapor jika diinginkan
- Kami tidak akan disclose detail sebelum fix dirilis

## Security Best Practices

Jika Anda kontribusi pada proyek:

1. Jangan commit credentials atau secrets
2. Gunakan environment variables untuk sensitive data
3. Follow secure coding practices
4. Test code untuk common vulnerabilities
5. Scan dependencies untuk known vulnerabilities

## Dependencies Security

- Regular security audits
- Update dependencies secara berkala
- Use tools seperti Dependabot
- Monitor security advisories

## Code Review Process

Semua code melalui review process untuk:
- Security vulnerabilities
- Code quality
- Best practices
- Performance issues
